# financial-statementsページの表示不具合修正

## 背景・目的

オーナーが本番URL（https://app-ebon-kappa-67.vercel.app/financial-statements）を実機で確認したところ、2つの表示不具合が見つかった。

1. 貸借対照表の説明文（`isSampleData`等に応じた3パターンの案内文）が、その上に表示される他のテキストと重なって文字化けして見える
2. 貸借対照表の「資産の部」「負債の部」「純資産の部」の各ボックスが、見出しは表示されるものの中身の行（現金及び預金・資産の部合計等の金額）が見えない

## 原因調査（コード確認済み）

`src/app/financial-statements/FinancialStatementsClient.tsx`を確認した。

**①のテキスト重なりは原因を特定済み**: 266行目の説明文`<p>`要素に`-mt-6`（`margin-top: -1.5rem`）が付与されている。

```tsx
<p className="text-xs text-stone-500 dark:text-stone-400 leading-relaxed max-w-2xl -mt-6">
```

この負のマージンは、直前に表示される見出し・免責文言（`page.tsx`側のヘッダー領域）の高さが特定の行数に収まることを前提に調整されたものと推測されるが、実機では免責文言が2行に折り返っており、その結果この`<p>`が上の要素に食い込んで重なって見える。固定の負マージンで隙間調整をしている箇所が根本原因。

**②の空欄表示は、静的なコード読解だけでは原因を特定できなかった**。テーブル自体は`{yen.format(balanceSheet.endingCash)}`のように値をバインドする作りになっており、マークアップ上は空欄になる理由が見当たらない。以下のいずれか（または組み合わせ）が疑われるため、実装時に実際にブラウザで再現させてから原因を確定すること（**推測で直さないこと**）:
- `balanceSheet`（`buildBalanceSheetForm`の戻り値）の値が実際に`0`または`NaN`になっており、`yen.format()`の出力が視覚的に空欄に見える（例: `NaN`が空文字列相当に見える等）
- ダークモード時の文字色コントラスト不足（`<td>`に明示的な文字色クラスが無く、親要素の文字色設定に依存しており、暗い背景で暗い文字色になっている）
- `useBalanceSheetData`フックが未ログイン/データ未投入時に返す値の形が、コンポーネント側の期待する形と食い違っている

## スコープ

**含む**:
- ①の文字重なり: 固定の負マージンをやめ、通常のフローに沿った余白（前の要素の`margin-bottom`、またはこの`<p>`の`margin-top`を`0`もしくは正の値）に置き換える
- ②の空欄表示: 上記3つの仮説を実機（ブラウザ）で再現・切り分けたうえで、特定できた原因を修正する

**含まない**:
- `2026-08-29-entry-auth-theme-nav-design.md`で扱うダークモードの一貫適用そのもの（本specは②の原因がダークモードのコントラスト不足だった場合のみ、このページに限定して対処する。全ページ共通のテーマ機構の設計は前者のspecの範囲）
- `balanceSheetForm.ts`等、`lib/tax/`側の計算ロジックの変更（今回はUI側の表示不具合が前提。仮に調査の結果、計算ロジック自体に不具合が見つかった場合はこのspecの範囲を超えるため、実装者は着手前にユーザーへ確認を挟むこと）

## テスト方針

- ①: 該当ページのスナップショット/レンダリングテストがあれば、余白変更後も崩れないことを確認。無ければ新規に追加は必須としない（視覚的な微調整のため）
- ②: 原因を特定した箇所に対して、再発防止のテストを追加する（例: 計算ロジックの不具合なら`balanceSheetForm.test.ts`にケース追加、表示側の不具合ならコンポーネントテストで金額が実際にレンダリングされることを検証）
- 既存の全テストがグリーンのまま維持されること
