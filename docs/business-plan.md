## 1. 重要な前提：法人としての法的形態について

「AIが代表を務める法人」は、日本の会社法上は成立しません（代表取締役は自然人である必要があります）。したがって:

- **ジャービス = CEO** は、対外的なブランド・プロダクト人格、および社内オペレーションの自動化主体として運用する（Slack/社内向けの「意思決定エンジン」「業務執行AI」という位置づけ）。
- **登記上の代表取締役 / 契約主体 / 銀行口座名義** は、修吾さん（または将来的に選任する自然人）が務める。
- 対外的なプレスリリースやLPで「CEO: Jarvis（AI）」と名乗ること自体は可能（ブランディングとして）だが、契約書・利用規約・特商法表記等の法的責任主体は必ず自然人/法人格として明記する。

この前提はプロダクトの信頼性にも関わるため、LPやTerms作成時に必ず反映する。

## 2. 法的ポジショニング（税理士法対応）

**選択: 本人申告支援ツール型**（freee会計・マネーフォワード クラウド確定申告と同じ枠組み）

- 税理士法第2条により、**税務代理・税務書類の作成・税務相談は税理士の独占業務**。
- 本サービスは以下に徹する:
  - 記帳の自動化（銀行・カード・請求書データの自動仕訳）
  - 税額計算・申告書データの自動生成（あくまで「下書き」「シミュレーション」表記）
  - e-Tax / eLtaxへの**送信操作は納税者本人が最終実行**（本人のマイナンバーカード/利用者識別番号での認証・送信）
  - 個別具体の税務相談には応じない（FAQ・一般的な制度解説にとどめる。必要に応じて提携税理士への送客動線を用意）
- UI/文言で「申告書は当社が作成します」ではなく「申告書の下書きを自動作成し、送信は自動で行えます（あなたの権限で）」という表現を徹底する。
- 将来的に「提携税理士監修プラン」をアドオンとして検討可能（別トラック、要顧問契約）だが**Phase 1のスコープには含めない**。

**要調査事項（要弁護士/税理士確認）**:
- freee/MFの利用規約・実装（本人送信の実装方法）のベンチマーク
- 電子帳簿保存法・インボイス制度対応の要件
- e-Tax/eLtaxのAPI提供状況（法人向けAPI、電子証明書の扱い、代理送信と本人送信の技術的差異）

## 4. プロダクトコンセプト

**コンセプト**: 記帳〜申告書下書き〜e-Tax/eLtax送信までを、AIエージェントが一気通貫で伴走する「セルフ申告のコパイロット」。既存クラウド会計（freee/MF）との違いは「自動化の深さ」と「価格」。

差別化ポイント（仮説）:
1. **AIによる仕訳の自動確定率を最大化** — 人間のレビューは例外処理のみ
2. **申告シーズンの申告書下書き自動生成 + 送信ガイド**（チェックリスト形式でe-Tax/eLtax送信まで誘導、または将来的にAPI連携で半自動化）
3. **低価格・低運用コスト前提の設計**（AIオペレーションで人件費を持たないため、freee/MFより安い価格帯を狙う）
4. **マイクロ法人特化の申告パターン**（法人税・消費税・年末調整をワンストップでカバー）

## 6. MVP（Phase 1）スコープ

**目的**: 「本当にランニングコストが下がるか」「AIの自動仕訳・申告書生成が実用精度に達するか」を最小構成で検証する。

含む:
- 銀行・カード明細の取り込み（CSV手動アップロード、または対応銀行API）
- AIによる自動仕訳（勘定科目・税区分の推定）
- フリーランス向け: 所得税確定申告書（青色申告決算書含む）の下書き自動生成
- マイクロ法人向け: 消費税・法人税の概算試算（申告書全体は自動化しない、まずは試算のみ）
- 生成した書類のe-Tax/eLtax送信手順ガイド（本人操作前提、UIでステップバイステップ）

含まない（Phase 2以降）:
- e-Tax/eLtax APIとの直接連携による送信の完全自動化
- 提携税理士連携プラン
- 年末調整・給与計算の自動化
- 法人税申告書のフル自動生成（別表対応など）

**成功指標（仮）**:
- AI自動仕訳の正解率 ○○%以上（要ベンチマーク設計）
- 申告書下書き生成〜送信完了までのユーザー作業時間（対freee/MF比較）
- MVPユーザーの解約率・満足度

## 8. 料金モデル（仮）

- ランニングコスト最小化が刺さる層なので、**税理士顧問料（月2〜5万円）より圧倒的に安い月額**を想定
- 例（要検証）: フリーランス ¥980〜/月、マイクロ法人 ¥2,980〜/月（申告シーズンのみのスポット価格も検討）
- 価格戦略は競合（freee/MF/やよいの申告）のプラン調査後に確定

## 9. 技術方針（概要、詳細設計は別ドキュメント）

- 会計データ基盤: 仕訳データモデル、証憑（レシート/請求書）OCR取り込み
- AIパイプライン: 仕訳推定モデル、税額計算ロジック（税制ルールのコード化 + LLMによる例外対応）
- 申告書生成: 国税庁/地方税ポータルの様式に沿ったデータ生成（XML/CSV、e-Tax/eLtax仕様準拠）
- 送信: 本人のマイナンバーカード/利用者識別番号による認証を前提としたフロー設計
- セキュリティ: 会計・税務データを扱うため、暗号化・アクセス制御・監査ログを初期から設計に組み込む

→ 技術アーキテクチャは別途 `docs/tech-architecture.md` として設計予定
